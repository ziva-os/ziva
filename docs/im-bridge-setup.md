# IM Bridge 连接指南

Ziva 的「连接手机」功能可以把 AI 助手接入到 **飞书（Feishu）** 或 **Telegram**，让你在手机上发送消息，Ziva 在桌面端收到后作为普通对话处理，并把回复发回 IM。

> 注意：Telegram Bot API 在中国大陆访问可能需要代理，请在配置时填写 `proxy_url`（支持 `http://host:port` 或 `socks5://host:port`）。

---

## 1. 通用概念

### 1.1 白名单（允许的发送者）

IM 消息默认任何人都能发给机器人，但 Ziva 采用 **fail-closed** 策略：只有白名单内的发送者才能触发 AI 对话。白名单为空时，所有消息都会被拒绝。

进入「连接手机」→「安全 · 允许的发送者（白名单）」，输入发送者 ID 后点击**添加**：

- **飞书**：使用用户的 `open_id` 或 `union_id`。
- **Telegram**：使用 Telegram 用户的 `user id`（数字）。

> **不知道发送者 ID？** 先让目标用户给机器人发送一条消息，消息会被拦截并出现在「等待审批的发送者」列表中，点击**允许**即可自动加入白名单。

### 1.2 默认工作区

IM 触发的对话会使用这里配置的默认工作区作为当前目录（cwd）。留空则使用当前 Ziva 中活跃的工作区。你可以直接填写路径，或点击「选择…」按钮从文件夹选择器里选择。

### 1.3 通道状态

每个平台会显示一个状态 pill：

| 状态 | 含义 |
|------|------|
| 已连接 | 机器人已在线，可以收发消息。 |
| 连接中 | 正在连接平台。 |
| 未连接 | 尚未配置或已断开。 |
| 错误 | 连接失败，卡片下方会显示错误信息。 |

## 2. 连接飞书（Feishu）

### 2.1 创建飞书应用

1. 打开 [飞书开放平台](https://open.feishu.cn/) 并登录。
2. 进入「开发者后台」→ 点击「创建企业自建应用」。
3. 填写应用名称（例如 `ZivaBot`）和描述，创建应用。

### 2.2 获取凭证

1. 进入应用详情页，点击左侧「凭证与基础信息」。
2. 复制 **App ID** 和 **App Secret**。
3. 在 Ziva 的「连接手机」中点击「连接」→ 选择「飞书」→ 填入这两个字段，点击「验证并连接」。

> App Secret 仅在创建时完整显示一次，请妥善保存。

### 2.3 启用机器人能力

1. 在飞书应用后台，点击「添加应用能力」→ 添加「机器人」。
2. 进入「事件与回调」→ 开启事件订阅，并订阅以下事件：
   - `im.message.receive_v1`（接收消息）
3. 确保机器人有权限读取群消息 / 私聊消息。如果缺少权限，Ziva 在连接时会返回权限错误，按提示在飞书后台添加即可。

### 2.4 获取发送者 ID

让目标用户给机器人发送一条任意消息，然后：

- 在 Ziva 的日志中查看该消息的 `sender.open_id`；或
- 通过飞书开放平台的「用户管理」接口查询用户的 `open_id` / `union_id`。

将该 ID 填入白名单即可。

## 3. 连接 Telegram

### 3.1 创建 Telegram Bot

1. 在 Telegram 中搜索并打开 **@BotFather**。
2. 发送 `/newbot`。
3. 按提示输入机器人名称（显示名称）和用户名（必须以 `bot` 结尾，例如 `ZivaHelperBot`）。
4. 创建成功后，BotFather 会返回一条消息，里面包含 **Bot Token**，格式类似：

   ```
   123456789:ABCDEFGHIJKLMNOPQRSTUVWXYZ1234567890
   ```

5. 复制该 token。

### 3.2 在 Ziva 中连接

1. 打开 Ziva「连接手机」→ 点击「连接」→ 选择「Telegram」。
2. 粘贴刚才复制的 **Bot Token**，点击「验证并连接」。
3. 连接成功后，状态会变为「已连接」。

### 3.3 获取 Telegram User ID

每个 Telegram 用户的 `user_id` 是数字。最简单的方式：

- 在 Telegram 中发送 `/start` 给你的机器人；
- 在 Ziva 日志中查看 `update.message.from.id`；或
- 让目标用户使用 **@userinfobot** 查询自己的 ID。

将数字 ID 填入白名单即可。

## 4. 图片输入

飞书和 Telegram 都支持接收图片消息。当白名单用户发送图片时，Ziva 会下载图片并将其作为 user message 的 image part 一起传给模型。如果当前模型支持 vision，AI 就能直接理解图片内容。

- **飞书**：需要机器人有读取图片 / 文件的权限，Ziva 会通过 `lark-oapi` 下载图片内容。
- **Telegram**：Bot 通过 `getFile` 接口下载图片；若配置了 `proxy_url`，下载走代理。

发送图片时，建议同时配一句文字说明，模型理解会更准确。纯图片消息也能处理，但结果可能不如图文结合稳定。

## 5. 回复格式：思考过程 + 工具调用

Ziva 对 IM 的回复不是只返回最终答案。`bridge.py` 会监听 `chat_with_events` 事件流，把以下信息也整理进回复：

- **思考过程**：当模型输出 `reasoning_delta` 时，IM 回复会附带「思考：…」摘要。
- **工具调用**：出现 `tool_start` / `tool_end` 时，回复会说明调用了哪些工具以及结果概要。

例如，当用户问"帮我分析这张图表"时，IM 收到的回复可能长这样：

```
思考：我需要先读取图片并提取关键数据...

工具：read_file / 使用 read_file 打开图片...

结果：图表显示 Q1 收入同比增长 23%，Q2 下降 5%...

结论：从图中可以看出...
```

这样即使不在桌面端，你也能看到 AI 做了哪些步骤，而不是只拿到一个"黑盒"答案。

## 6. 常见问题

### 6.1 连接飞书后提示「权限不足」

在飞书应用后台：

1. 进入「权限管理」。
2. 添加并申请以下权限：
   - `im:chat:readonly`
   - `im:message:send`
   - `im:message.group_msg`
   - `im:message.p2p_msg`
   - `im:image:readonly`（如需图片输入）
   - 读取用户基本信息相关权限（用于获取 open_id）。
3. 重新发布应用并点击「验证并连接」。

### 6.2 Telegram 提示 401 / Unauthorized

通常是因为 Bot Token 复制不完整，或者 token 已被撤销。请返回 @BotFather 发送 `/mybots`，选择机器人后重新生成 token。

### 6.3 机器人已连接，但发送消息没有反应

1. 检查白名单是否包含该发送者 ID。如果不确定，先发送一条消息，然后在「等待审批的发送者」列表中点击「允许」。
2. 检查默认工作区是否正确。如果工作区为空，确认当前 Ziva 中活跃工作区是你期望的目录。
3. 查看 Ziva 日志中是否有 adapter 错误。

### 6.4 如何断开机器人？

在「连接手机」列表中，已连接的机器人右侧会显示「断开」按钮。点击即可停止该平台的连接，Ziva 将不再接收该机器人的消息。

---

## 7. 安全建议

- **不要把 Bot Token / App Secret 直接提交到代码仓库。** 这些凭证应通过 Ziva 的 UI 输入并存储在本地配置中。
- 白名单建议只添加你信任的联系人。
- 如果不需要某个平台，请及时点击「断开」，避免机器人长期在线被他人扫描到。
